# P0-9.3 R1　亮屏双击返回时钟

## 本轮验收决定

正常 Android 环境下，已启用专机的用户用实体电源键完成两次短按和松开，应直接得到能触摸的时钟、系统 LOCKED、flags=80。维护暂停优先于所有尚未交付的返回请求。基本紧急拨号独立检查。原厂五击 SOS 快捷手势、原厂相机快捷以及它们与普通双击的优先级均已移出强制验收项。三击及以上仍作误触测试。

## 资源配置重新评估

已有同固件、同资源表的 idmap2 实验已经验证，在正规 product 资格下，双击行为与目标两项可映射为 3 和显式 Activity。仅具 public 资格的 overlay 被拒；四个原厂映射单独回读为 0/空。此结果可用于产品的按键功能选择。现场 OMS 是否认可新 overlay 仍取决于实际安装身份和分区配置。

本轮核对已留存的 CPDAY10 DEX。PhoneWindowManager.getMaxMultiPressPowerCount 的 0012–001d 表明这台手机在三击行为为 0、双击非零时取最大次数 2。SingleKeyGestureDetector.interceptKeyDown 的 0142、014c 读取最大次数，达到上限后可在第二次按下立即派发。PhoneWindowManager.launchTargetActivityOnMultiPressPower 的显式 Intent 没有第二次释放时间。单击再长按与两个短击共享该按下时刻。把目标改为时钟，仍会有误触，也没有横跨维护暂停的过期判据。

把三击配置为另一个受支持的行为会提高计数上限，改变第三击的原厂动作；MAX=3 时可经 interceptKeyUp 的延迟分支派发二击。它仍然不向 Activity 传递首击、用户或模式转换前后的时序。板上若已有厂商接口能够提交带时间信息的完整双击，可以直接对接本轮协议。推荐产品代码复用原生单击/长按策略，将双击送入本轮系统适配器。原始无 action 的 RRO 目标继续保留供历史诊断。此次无需更改现用手机的全局设置、按键驱动或安全防护。

## 已实现的交付链路

| 位置 | 行为 |
| --- | --- |
| 产品系统侧 StationPowerShortcut | 由系统策略在同一 Looper 喂入受信、默认显示器、user 0 的有序实体电源 DOWN/UP。依据系统多击/长按配置及单调时钟，处理首击亮屏、去抖、取消和过期。没有等候 SOS 服务答复的步骤。 |
| StationPowerArbiter | 只接受两次完整短按，首击至第二次按下至少 40 ms，且在系统多击窗口内；第二次松开后等待一个多击窗口以排除第三击。超出再派发宽限 100 ms 时丢弃。在源端取消后，旧事件不能重放。40 ms 与 100 ms 是候选参数，应记录真实用户的操作成功率。 |
| 系统至时钟 | 固定包与接收器，以系统身份向 user 0 发送显式信号，包含开机编号、首次按下及第二次松开的 elapsedRealtime 毫秒。接收器受 android.permission.STATUS_BAR_SERVICE 保护。应用未申请这项权限。 |
| 0.6.13-dev 接收及窗口交接 | 核对用户存储、模式与维护暂停、Owner、真实允许名单及功能、NONE、亮屏、Keyguard 和音频模式。在 CE 中预留一次请求，然后定向启动未导出的 PowerClockEntry。收到 Activity 时先检查，实际获得前台焦点才消费并转为 CLOCK。调用原有锁定逻辑并读回状态。 |
| 时效与维护暂停 | 请求从第二次松开起最多保留 2 秒；完整序列最长 1 秒。首次按下必须晚于本次模式切换。暂停、重启、重新启用或退出会使旧请求失效；同一时刻最多一个尚待窗口接收的请求。首次覆盖旧版且缺模式时间边界时，第一次信号建立边界，需一次新的双击；正常退出再进入 Android 会自动建立边界。 |

产品接线位于 Codex 的系统集成范围。现有板级策略须在默认显示器的正常交互路径向 StationPowerShortcut.onPowerKey 交付两个方向的完整事件，使用相同的系统策略队列序列化输入与定时回调。Policy.currentGeneration 应来自当前用户/显示会话；切用户、灭屏、锁屏、按键组合、通话或拨号界面、原厂长按菜单进入时调用 cancel，并在不适用期间返回负值。两种 elapsed/uptime 时基在手势中出现明显偏差时丢弃请求。保留系统正常单击超时调度与长按处理，每次手势只配置一个双击执行方。未经核对的普通应用、后台定时器、通用 Root 接口均不构成这个信号源。

开发 APK 已包含接收端，系统端 Java 源码、Soong 声明及离线 JAR 在审查包内。JAR 用于主机验证或集成审查。库存 ROM 与当前 naozho_boot 尚未接入此系统发送端，单独覆盖 APK 无法产生实体双击信号。仓库未包含可构建的同版 CPDAY10 输入策略产品源码。下一步由 Codex 接入匹配的产品构建或厂商已支持的事件回调，DSH 只需部署获准的成品、操作设备和记录结果。

## DSH 后续验收

目前无需手机在线。以后拿到同时包含系统发送端与应用接收端的、可单独撤回的同板产品后，再执行下表。先确认备用 Android 桌面、维护暂停和独立系统恢复已可用；验收期间不拨打真实紧急号码。

| 场景 | 操作与通过条件 |
| --- | --- |
| 基本双击 | 从明确开发退出后的普通 Android 模式开始，亮屏、无锁屏、独立专机仍启用。实体短按并释放两次，共做 10 轮。逐轮记录第二次松开到时钟首次可触摸的耗时、实际成功次数、是否出现多份任务。实际时钟应为 LOCKED、80、名单仅 com.naozho.clock。 |
| 误触 | 单击熄屏及单击唤醒；第二下按住；普通长按菜单；三击和五击；从息屏开始的连击。均不得误入时钟。确认单击和长按仍可使用。无需按键组合触发 SOS。 |
| 重复与退出 | 已在时钟时再双击，不产生新启动或重复锁定。手指连续上滑 2 次、5 次后能触摸；取消开发退出保持锁定，确认退出后能停留在普通 Android，再次双击能返回。 |
| 暂停与恢复 | 维护暂停后双击，手机停留在原环境；暂停跨重启仍有效。在模拟时序中验证请求已送达、窗口将获焦但维护暂停生效的竞态。恢复专机后只有新的双击可用。 |
| 基本紧急拨号 | 在普通 Android，以及从时钟明确退出后的 Android，检查系统拨号入口可达、可操作；使用隔离的电话测试环境检查拨号/通话中双击不抢焦。另记录原厂 LOCKED 下可用的紧急入口。无法验证的路径标为待测，不将五击表现计入双击验收。 |

验证失败时记录同次开机的系统裁决、接收情况、前台焦点和系统 Lock Task 读回。默认 HOME、首次开机画面和天气等事项与本轮双击分开记账。

## 撤回

仅覆盖应用时，通过现有明确退出和维护入口，以同包同签名的 0.6.9-rollback-dev / 28 覆盖恢复已知应用行为，保留 Owner 和数据；应用覆盖回滚已做静态签名与版本比对，真机尚待验收。系统侧必须另有独立撤销入口，用于关闭产品双击路由并恢复原生按键配置。若系统改造导致界面不可操作，使用已在相同板号演练过的独立恢复方案。无匹配产品和恢复条件时只使用本次离线产物，不发布可刷镜像。
