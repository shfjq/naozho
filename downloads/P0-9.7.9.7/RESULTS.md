# CPDAY10 Root 全局唤醒候选的交付与验收记录

## 本次可安装的功能

0.6.20-dev / 35 与 naozho_wake 1.5.0 / 7 是一对待真机验收的候选。Root 观察器处理真实显示状态和电源状态，识别 user 0 的普通前台任务。前台应用不需要登记，用户不需要设置无障碍服务或摆放桌面小部件。此版本新增了由 Root 向 ActivityTaskManager 请求恢复时钟的路径。原应用留在自己的任务中，正常退出、维护暂停、独立锁定和开机模块沿用现有设计。

此前生产代码对第二个可见应用窗口直接否决。现在会结合 Window Token、服务端 ActivityRecord、用户、显示器、任务号、实际 UID、遮挡范围、层序和输入属性核对普通启动窗口。无法确认归属、真实可交互的未知覆盖、受保护窗口、来电和焦点不稳定时会放弃该次请求。有些共享的系统设置页面承载认证或权限界面，缺少普通路由证据时同样会放弃。真实浏览器多窗口日志本轮并未采到；新增多窗口样例属于离线回归。

## 交接顺序

1. 观察真实息屏和亮屏边沿，按独立电源证据确认完整唤醒。AOD 和 DREAMING 不能仅凭显示器 ON 触发正式时钟。
2. 受保护的显式 RETURN 和 COMMIT 各自取得 AMS 投递证明，并校验发送 UID。COMMIT 的接收端仅同步保存精确预留票据。
3. Root 在启动前核对任务仍为同一来源、维护状态及新鲜度，读取预留记录，再向系统请求一次启动固定的私有 PowerClockEntry。应用不从唤醒广播里启动前台界面。复用已有时钟 Activity 时不清除原任务。
4. Android 允许时为真实 MainActivity 创建黑色系统启动窗口。热启动可能直接恢复已有窗口。该画面发生在正式启动请求之后。
5. 核对匹配同一唤醒周期、request_id 和发送 UID 的硬件首帧回执、窗口焦点及 LOCKED。应用写回执前读回 flags=80、允许名单仅时钟。遇到拒绝或超时，记录失败阶段；同一周期不重复拉起。

## 全屏黑幕的当前边界

**本安装包尚未实现亮屏至正式启动之间的全屏遮挡和底层触摸阻断。** 窗口、SurfaceFlinger 和进程权限的只读探测只在模块启动时执行。该固件审核到的独立 Root 接口无法提供原普通窗口专属的画面与输入挂载权。以全显示器通用悬浮窗替代会在新来电或认证 Activity 出现时留下遮挡及触摸竞争。详细方法、固件哈希及不同窗口层级见 WINDOW.md。

本包成功接管时记录 HANDOFF_COMPLETE 并注明 mask=not_submitted。MASK_REFUSED_AT 与 ROOT_ATM_ACCEPTED_AT 分别表示遮罩未提交和系统接受启动。两者均不构成物理显示证据。批准部署后的浏览器测试可以验收正式返回、任务保留及实际观感，不能据此把未提交的黑幕记为通过。

源码包另含 platform/wake-transition 原型。它使用真正的嵌入输入通道，要求宿主在窗口管理器锁内核对来源窗口、父 Surface、输入令牌及几何，并在同一次窗口事务中提交或撤销黑层。API 35 和 36 的编译和 34 项租期、代际及异常撤销断言已通过。此原型未链接入安装包；接入需要与当前固件匹配的厂商 WM 源码或提供同等能力的受支持接口、原版镜像及独立恢复验证。
